# Mythwake v2 – Architecture

Mythwake v2 is a ground-up rebuild. Nothing from the v1 code base is referenced or copied.
Game design: `docs/GAME_DESIGN.md` (source of truth). Combat rules: `docs/COMBAT.md`. Progress: `docs/STATUS.md`.

## Goals

- **Server-authoritative ready from day one.** All game rules live in a pure C# library (`Mythwake.Core`) with no
  Unity dependency. The client runs it locally today; a .NET backend can run the very same assembly later, so client
  prediction and server validation can never drift apart.
- **Deterministic combat.** Integer math (fixed-point permille), tick time and a seeded PCG32 RNG. Same input → same
  battle, on every platform. The simulation produces an event log; the presentation only *plays it back*.
- **Data-driven content.** Heroes, skills, stages, banners and buildings are JSON content (`Assets/Mythwake/Content`),
  validated by `ContentValidator` in tests and on import. Designers change numbers without touching code.
- **Thin Unity layer.** MonoBehaviours only present state and forward input. No game rules in views.

## Assemblies

| Assembly | References | Purpose |
|---|---|---|
| `Mythwake.Core` | – (no Unity) | Definitions, player state, commands, combat simulation, economy, idle, summon, RNG, math |
| `Mythwake.Content` | Core, Newtonsoft (no Unity) | JSON format of content files (camelCase, enums as strings, unknown fields are errors) |
| `Mythwake.Game` | Core, Unity | Composition root, content loading, save, time, authority (local now, remote later), app state machine |
| `Mythwake.Presentation` | Core, Game, Spine | Battle playback (Spine heroes, VFX, damage numbers, cut-ins, camera shake), Home scene |
| `Mythwake.UI` | Core, Game, Presentation | UI Toolkit screens built in C# + one USS theme, navigation, widgets, autopilot smoke run |
| `Mythwake.Editor` | all | Project setup (URP, scene, panel), content catalog, portrait renders, import settings, builds |
| `Mythwake.Core.Tests` | Core | Rule tests (combat determinism, mechanics, progression) |
| `Mythwake.Content.Tests` | Core, Content | Loads the real content and runs every hero through the rules |

Core, Content and their tests also build outside Unity: `dotnet test Tools/CoreTests` (about a second). Run it before
every commit that touches rules or content.

## Rules flow

```
UI / input ──► IGameAuthority.Execute(command) ──► Core command validates + mutates PlayerState ──► result + state events ──► UI refresh
                     │
                     ├─ LocalAuthority  (now): runs Core in-process, saves to disk
                     └─ ServerAuthority: predicts locally, sends commands to the Go API, which runs the same Core in the rules service (docs/SERVER.md)
```

Commands are plain data (`StartStageBattle`, `LevelUpHero`, `ClaimAfkRewards`, `Summon`, …). Each command has one
handler in Core that checks costs/unlocks, mutates `PlayerState`, and returns a typed result. Time and randomness are
injected (`IClock`, seeded RNG), never read from the environment inside Core.

## Battle flow

```
BattleSetup (teams, seed, rules) ──► BattleSimulator.Run() ──► BattleResult (winner, events[], stats)
                                                                     │
                                       BattlePlayback (Presentation) ◄┘  plays events on Spine units,
                                                                         driven by animation events (hit/cast/cutin/shake)
```

Manual ultimates: the player's taps are recorded as `UltimateRequest(tick, unit)` and fed into the simulator, which
re-simulates deterministically. The server can validate the same request list.

## Folders

```
Assets/Mythwake/
  Runtime/Core/          pure rules
  Runtime/Game/          composition root, services
  Runtime/Presentation/  battle + world views
  Runtime/UI/            UI Toolkit screens (*.uxml, *.uss, *.cs)
  Editor/                importers, validation, build
  Runtime/Content/       JSON (de)serialisation of content
  Content/Heroes/<id>/   <id>.hero.json (stats + kit) and the Spine export (json, atlas.txt, png)
  Content/Data/          other JSON content (stages, banners, buildings)
  Scenes/Main.unity      single scene: camera, battlefield, UI document, AppRoot (generated by Mythwake ▸ Setup Project)
  Settings/              URP asset, panel settings, placeholder background
  Tests/Core, Tests/Content
Tools/CoreTests/         dotnet project that compiles Core + Content + tests outside Unity
Tools/ContentPipeline/   content scripts (migrate_kits.py: one-time kit -> hero JSON migration)
```

## Conventions

- C# 9, nullable-friendly style, `sealed` by default, no static mutable state except the composition root.
- Names from `docs/GAME_DESIGN.md` only (currencies, buildings, factions, aspects). No invented lore terms.
- Every currency and item id is a constant in `Core/Ids.cs`; content refers to them by id.
